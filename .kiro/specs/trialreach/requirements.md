# Requirements Document

## Introduction

TrialReach finds the research deserts of Massachusetts: counties where many adults have a disease but few recruiting clinical trials are within reach. It serves hospital research offices, trial sponsors and state health officials who need to decide where to open the next study site and which communities to reach. The system downloads public data once, scores counties for nine diseases, shows the result on a Streamlit map, and can write a short recruitment brief with an optional LLM. TrialReach scores places, never people. Scope excludes patient accounts, personal health data, eligibility decisions, drive-time routing and states other than Massachusetts.

## Glossary

- **TrialReach**: The whole application (data fetcher, scoring module, LLM module and Streamlit UI).
- **Data_Fetcher**: The script `fetch_data.py` that downloads datasets into `data/`.
- **Scorer**: The module `deserts.py` containing pure scoring functions with no Streamlit imports.
- **LLM_Client**: The module `llm.py` exposing `generate(prompt) -> str | None`.
- **UI**: The Streamlit application `app.py`, which only displays results.
- **Disease**: One of nine conditions, identified by CDC measure id: DIABETES, OBESITY, DEPRESSION, BPHIGH, CHD, COPD, CASTHMA, STROKE, CANCER.
- **Trial**: A recruiting ClinicalTrials.gov study identified by an NCT id.
- **Trial_Site**: One Massachusetts location of a Trial that has a geographic point.
- **Reach_Radius**: 25 miles, straight-line distance.
- **People_Per_Trial**: Affected people in a county divided by (population-weighted trials in reach + 1).
- **Desert_Score**: Integer from 0 to 100 equal to round(100 × People_Per_Trial ÷ maximum People_Per_Trial across the 14 counties).
- **Affected_People**: County prevalence percent ÷ 100 × CDC total population.
- **Candidate_Hospital**: A hospital with FACILITY_TYPE equal to "Acute Hospital".
- **EJ_Town**: A Massachusetts town containing environmental-justice block groups.
- **Rule_Brief**: The text produced by `outreach_brief()`, a rule-based recommendation.
- **AI_Brief**: A resident flyer and a hospital note generated by the LLM_Client.
- **Resident_Flyer**: AI_Brief text of at most 120 words in the chosen language at about grade 6 reading level.
- **Hospital_Note**: AI_Brief text of three short lines in English for the hospital research office.
- **Saved_Data**: The JSON and GeoJSON files in `data/` plus `data/fetched_at.txt`.

## Requirements

### Requirement 1: Data download

**User Story:** As a developer, I want to download all datasets once, so that the app runs without network access.

#### Acceptance Criteria

1. WHEN the Data_Fetcher is run, THE Data_Fetcher SHALL save `towns.geojson`, `towns.json`, `cdc_places.json`, `trials.json`, `hospitals.json`, `ej.json` and `fetched_at.txt` in `data/`.
2. THE Data_Fetcher SHALL request each endpoint with a 60-second timeout and up to 3 retries.
3. WHEN an ArcGIS layer returns a page of 1000 rows or sets `exceededTransferLimit`, THE Data_Fetcher SHALL request the next page using `resultOffset` and `resultRecordCount=1000`.
4. WHEN a ClinicalTrials.gov response contains `nextPageToken`, THE Data_Fetcher SHALL request the next page until the token is absent.
5. THE Data_Fetcher SHALL query ClinicalTrials.gov with `query.locn=Massachusetts`, `filter.overallStatus=RECRUITING`, `pageSize=1000` and the search term of each Disease.
6. THE Data_Fetcher SHALL request the ClinicalTrials.gov fields NCTId, BriefTitle, Condition, Phase, LocationFacility, LocationCity, LocationState and LocationGeoPoint.
7. THE Data_Fetcher SHALL save each Trial as `{nct, title, conditions, phases, sites:[{facility, city, lat, lon}]}` keyed by measure id, keeping only locations with state "Massachusetts" and a geoPoint.
8. THE Data_Fetcher SHALL convert `INTPTLAT20` and `INTPTLON20` strings to floats in `towns.json`.
9. THE Data_Fetcher SHALL save the CDC PLACES rows filtered to stateabbr 'MA', data_value_type 'Crude prevalence' and the nine Disease measure ids.
10. THE Data_Fetcher SHALL save hospital latitude and longitude from the geometry y and x values and store null bed counts as 0.
11. THE Data_Fetcher SHALL save only EJ block groups where `EJ='Yes'`.
12. WHEN a download finishes, THE Data_Fetcher SHALL write the current time to `data/fetched_at.txt`.
13. IF an endpoint still fails after 3 retries, THEN THE Data_Fetcher SHALL report which dataset failed and exit with a non-zero status.
14. WHEN the Data_Fetcher makes HTTP requests, THE Data_Fetcher SHALL call `truststore.inject_into_ssl()` first, and continue if the `truststore` import fails.

### Requirement 2: Data loading and distance

**User Story:** As a developer, I want clean data frames and a distance function, so that scoring is testable.

#### Acceptance Criteria

1. WHEN `load_all()` is called, THE Scorer SHALL return towns, shapes, places, trials, hospitals, ej and fetched_at read only from Saved_Data.
2. THE Scorer SHALL join EJ records to towns by upper-casing MUNICIPALITY and add a county column.
3. THE Scorer SHALL compute `miles()` as haversine distance with Earth radius 3958.8 miles and accept scalars or numpy arrays.
4. THE Scorer SHALL compute all town-to-site distances with numpy broadcasting.

### Requirement 3: Research Desert Score

**User Story:** As a state health official, I want one comparable score per county and disease, so that I can see which county is most under-served.

#### Acceptance Criteria

1. WHEN `trial_sites()` is called for a Disease, THE Scorer SHALL return one row per Trial and Trial_Site, assigning each site to the county of the nearest town center.
2. WHEN `town_access()` is called, THE Scorer SHALL add `nearest_miles` as the minimum distance from the town to any Trial_Site.
3. WHEN `town_access()` is called, THE Scorer SHALL add `trials_in_reach` as the count of distinct NCT ids with a Trial_Site within the Reach_Radius.
4. WHEN `county_scores()` is called for a Disease, THE Scorer SHALL return one row for each of the 14 Massachusetts counties, sorted worst first.
5. THE Scorer SHALL compute county trials in reach and average miles as population-weighted means of town values, using POP2020.
6. THE Scorer SHALL compute People_Per_Trial as Affected_People divided by (county trials in reach + 1).
7. THE Scorer SHALL compute Desert_Score as defined in the Glossary, so the worst county scores 100.
8. THE Scorer SHALL include in each county row the prevalence, the CDC low and high confidence limits, trials in county (distinct NCT ids with a site in the county) and People_Per_Trial.
9. WHEN `county_scores()` is called for all nine Diseases, THE Scorer SHALL finish in under 2 seconds in total.
10. THE Scorer SHALL expose the score formula as a pure helper, `desert_score(affected, trials_in_reach)`, usable without loaded data.

### Requirement 4: Map and page layout

**User Story:** As a trial sponsor, I want a map and ranking for a chosen disease, so that I can see where trials are missing.

#### Acceptance Criteria

1. THE UI SHALL set the page title "TrialReach", icon "🌵" and wide layout.
2. THE UI SHALL provide a sidebar with a Disease selectbox of nine labels, a "Color the map by" radio with "Research Desert Score (county)" and "Miles to nearest trial (town)", a "Show trial sites" checkbox on by default, a "Show acute hospitals" checkbox off by default, and a one-sentence score explanation.
3. THE UI SHALL show the subtitle "Finding the research deserts of Massachusetts. Food deserts have a name. Research deserts don't."
4. THE UI SHALL show four metrics: recruiting Trials in Massachusetts for the Disease (distinct NCT count), the share of those Trials with a Suffolk site, the worst county with its People_Per_Trial, and the gap versus Boston (worst People_Per_Trial ÷ Suffolk People_Per_Trial) with the Suffolk People_Per_Trial as small text.
5. THE UI SHALL draw a `go.Choroplethmap` on `towns.geojson` with `featureidkey="properties.TOWN20"`, the "Reds" colorscale and white 0.3 px borders.
6. WHILE the map mode is "Research Desert Score (county)", THE UI SHALL color each town by its county Desert_Score from 0 to 100.
7. WHILE the map mode is "Miles to nearest trial (town)", THE UI SHALL color each town by `nearest_miles` with the color maximum at the 98th percentile.
8. WHILE "Show trial sites" is checked, THE UI SHALL draw blue `go.Scattermap` dots for Trial_Sites, deduplicated by facility, latitude and longitude.
9. WHILE "Show acute hospitals" is checked, THE UI SHALL draw green `go.Scattermap` dots for Candidate_Hospitals.
10. THE UI SHALL use map style "carto-positron", center (42.15, -71.75), zoom 6.9 and height 560, and disable scroll zoom.
11. THE UI SHALL show a ranking table of all 14 counties, worst first, with County, Desert Score (progress bar 0–100), People per nearby trial, % adults, Trials ≤25 mi and Miles to nearest.
12. THE UI SHALL display UPPERCASE place names in Title Case.
13. THE UI SHALL compute all scores through the Scorer and cache `load_all` and `county_scores` results.

### Requirement 5: County deep dive

**User Story:** As a hospital research office, I want details for one county, so that I know whether to host a study and whom to reach.

#### Acceptance Criteria

1. THE UI SHALL provide a "Look closer at a county" selectbox that defaults to the worst county.
2. WHEN a county is selected, THE UI SHALL show the Rule_Brief and the CDC 95% prevalence range as a caption.
3. WHEN a county is selected, THE UI SHALL show a table of the 8 nearest recruiting Trials measured from the county's population-weighted center, with Miles, Study, Phase, Site city and an "Open" link to `https://clinicaltrials.gov/study/{nct}`.
4. WHEN `candidate_hospitals()` is called for a county, THE Scorer SHALL return Candidate_Hospitals with `beds` equal to ICU + MED_SURG + PEDIATRIC and `nearest_trial_miles`, sorted by beds descending.
5. WHEN a county is selected, THE UI SHALL show a table of Candidate_Hospitals with Hospital, Town, Licensed beds, ICU beds and Miles to nearest trial.
6. WHEN `ej_summary()` is called for a county, THE Scorer SHALL return the total EJ residents and a per-town table with EJ population, neighborhoods and a population-weighted limited-English percent.
7. WHEN a county is selected, THE UI SHALL show the top 10 EJ_Towns under the heading "Where outreach has to try harder".
8. WHEN `outreach_brief()` is called, THE Scorer SHALL return a non-empty markdown recommendation built from the Disease, county row, state prevalence, hospitals and EJ data.
9. IF a county has no Candidate_Hospitals, no nearby Trials or no EJ_Towns, THEN THE UI SHALL show an `st.info` message in friendly language instead of an error.

### Requirement 6: AI brief with fallback

**User Story:** As a research office, I want a ready-to-use flyer and note in a resident's language, so that outreach can start quickly.

#### Acceptance Criteria

1. THE UI SHALL provide a Language selectbox with English, Spanish, Portuguese, Haitian Creole and Chinese, and a "Write recruitment brief" button in the county deep dive.
2. WHEN the user clicks "Write recruitment brief", THE UI SHALL send the LLM_Client a prompt containing only these facts: county, Disease, prevalence, state average prevalence, People_Per_Trial, Trials within 25 miles, top Candidate_Hospital and town, the 3 nearest Trial titles with NCT ids, and the EJ_Town with the highest limited-English percent.
3. THE UI SHALL include in the system prompt the rules: use only the given facts; do not invent numbers, trials or phone numbers; never say the reader qualifies, and say "talk to your doctor or the study team"; mention that trial details are on ClinicalTrials.gov; use friendly plain language without medical advice.
4. WHEN the LLM_Client returns text, THE UI SHALL show a Resident_Flyer in the chosen language and a Hospital_Note.
5. WHERE `LLM_PROVIDER` equals "bedrock", THE LLM_Client SHALL call the Amazon Bedrock Converse API with the model in `LLM_MODEL`.
6. WHERE `LLM_PROVIDER` equals "anthropic", THE LLM_Client SHALL call the Anthropic API with `ANTHROPIC_API_KEY` and the model in `LLM_MODEL`.
7. IF `LLM_PROVIDER` is unset, the call raises an error, or the call exceeds 20 seconds, THEN THE LLM_Client SHALL return `None` without raising an exception.
8. IF `generate()` returns `None`, THEN THE UI SHALL show the Rule_Brief and the caption "AI brief unavailable — showing the standard recommendation."
9. THE UI SHALL cache each result in `st.session_state` by (county, Disease, language) and reuse it on repeated clicks.
10. THE TrialReach SHALL read credentials only from environment variables and keep API keys out of source code and git.
11. THE TrialReach SHALL list in `requirements.txt` only the LLM SDK that is actually used.

### Requirement 7: Privacy, safety wording and citations

**User Story:** As a state health official, I want clear limits and sources on screen, so that the tool is not mistaken for medical advice.

#### Acceptance Criteria

1. THE TrialReach SHALL score places only and SHALL use only public place-level data.
2. THE TrialReach SHALL use wording that tells readers to talk to their doctor or the study team and avoid stating that a person qualifies for a Trial.
3. THE UI SHALL show a footer with the text "TrialReach scores places, never people. Not medical advice. Distances are straight-line from town centers. Licensed beds are not live occupancy."
4. THE UI SHALL show in the footer links to ClinicalTrials.gov (U.S. NLM), CDC PLACES 2023 county crude prevalence and MassGIS (Census 2020 towns, hospitals, EJ 2020 block groups).
5. THE UI SHALL use plain, simple language for all on-screen text.

### Requirement 8: Offline operation

**User Story:** As a hackathon judge, I want the app to open without internet, so that the demo works anywhere.

#### Acceptance Criteria

1. THE UI SHALL read all datasets from the committed Saved_Data and make no data requests to the network at run time.
2. WHEN Saved_Data is present, THE UI SHALL open in under 5 seconds.
3. WHEN no LLM environment variables are set, THE UI SHALL display every view without error.
4. IF a Saved_Data file is missing, THEN THE UI SHALL show a message telling the user to run `fetch_data.py`.

### Requirement 9: Automated tests

**User Story:** As a developer, I want unit and property-based tests, so that scoring stays correct.

#### Acceptance Criteria

1. WHEN `python -m pytest -q` is run, THE test suite SHALL pass using Saved_Data and no network.
2. THE test suite SHALL check that `miles(42.36, -71.06, 42.10, -72.59)` returns a value from 75 to 85.
3. THE test suite SHALL check that `county_scores` returns 14 counties for each of the nine Diseases.
4. THE test suite SHALL check that every Desert_Score is from 0 to 100 and the maximum equals 100.
5. THE test suite SHALL check that prevalence has no missing values and every town has `nearest_miles`.
6. THE test suite SHALL check that `candidate_hospitals`, `ej_summary` and `outreach_brief` run for every Disease and county and that the brief is non-empty.
7. THE test suite SHALL check that Hampden diabetes People_Per_Trial is more than 10 times Suffolk diabetes People_Per_Trial.
8. THE test suite SHALL check that `generate()` returns `None` when no LLM environment variables are set.
9. FOR ALL generated inputs with prevalence 1–40%, population 1,000–1,000,000 and trial counts 0–200, THE Scorer SHALL produce scores from 0 to 100 with a maximum of exactly 100.
10. FOR ALL generated inputs, adding trials to one county SHALL NOT increase that county's People_Per_Trial.
11. FOR ALL generated inputs, increasing Affected_People in one county SHALL NOT decrease that county's People_Per_Trial.
12. FOR ALL generated coordinate pairs a and b, `miles(a, b)` SHALL equal `miles(b, a)` and `miles(a, a)` SHALL equal 0.
13. FOR ALL valid Trial records, serializing to JSON then loading SHALL produce an equivalent record (round-trip property).
